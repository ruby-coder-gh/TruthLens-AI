Executive Summary

VeritasRAG is a document-intelligence platform that lets organizations ask natural-language questions over their private knowledge base and receive accurate, cited, trustworthy answers — with the entire AI pipeline running locally and at zero licensing cost.

Unlike a generic "chat-with-PDF" demo, VeritasRAG is built around one obsession: truth and traceability. Every answer is grounded in retrieved evidence, scored for confidence, linked back to the exact source passage, and automatically refused when the documents don't support it. A self-correcting retrieval loop and a multimodal understanding engine push answer quality beyond what a standard RAG pipeline achieves.

One-line pitch: "Perplexity for your private documents — fully offline, fully free, and engineered so it never makes things up."

02

Problem Statement

Knowledge is buried in documents nobody has time to read, and the AI tools that could help create three real problems:

🔒Privacy

Cloud LLMs require uploading sensitive contracts, medical records, and internal docs to third-party servers — a non-starter for regulated industries.

💸Cost

Commercial API pricing scales with every query, locking out students, researchers, and small teams.

🌀Hallucination

Standard chatbots invent plausible-but-false answers with no citations, making them dangerous for high-stakes decisions.

VeritasRAG solves all three: local execution (privacy), open-source models (cost), and a grounding-and-verification core (trust).

05

Unique Differentiators

These are the features that separate VeritasRAG from every "chat-with-PDF" tutorial. This is the heart of the project.

★ Signature Feature

🔁 Self-Correcting RAG (CRAG)

The system grades its own retrieved evidence before answering. If relevance is low, it automatically rewrites the query and re-retrieves — and only then generates. A loop that critiques itself instead of confidently answering from bad context.

→ retrieval grader + query rewrite loop (LangGraph + Ollama)
★ Trust Engine

🎯 Groundedness & Confidence Score

Every answer ships with a 0–100 "trust score" showing how well it is supported by the source passages. Low score → the UI flags it. High-stakes answers become auditable, not just plausible.

→ NLI cross-check of answer vs. evidence

Computation: the answer is split into individual claims; each claim is paired with its supporting chunk and passed through a local NLI model (e.g. cross-encoder/nli-deberta-v3-base) to get an entailment probability. Trust score = the minimum entailment probability across claims (not the average — one unsupported claim should sink the whole answer) × 100, blended with the retriever's top-k relevance score at a 70/30 weight.

Thresholds: ≥ 75 shown as high-confidence (green), 50–74 shown with a "verify this" amber flag, < 50 triggers the hallucination guardrail and the system refuses to answer outright. Thresholds are tuned against the golden dataset in Section 09, not picked arbitrarily.

★ Transparency

🔍 "Why This Answer?" Explainability Panel

A glass-box panel reveals exactly which chunks were retrieved, their relevance scores, and which sentences fed the answer. Most RAG apps are black boxes — VeritasRAG shows its work.

→ retrieval trace + per-chunk score surfaced to UI
★ Multimodal

🖼️ Charts, Tables & Diagrams Understanding

Answers questions about visual content inside PDFs — figures, tables, scanned diagrams — not just plain text. Ask "what was the Q3 revenue in Figure 4?" and get the number.

→ LLaVA / table-transformer on extracted page images
★ Inline Citations

📌 Click-to-Source Highlighting

Each claim in the answer is a clickable footnote that jumps to and highlights the exact sentence in the original document viewer — the Perplexity experience, fully local.

→ span-level provenance mapping
★ Self-Improving

👍 Feedback-Driven Retrieval Loop

Thumbs up/down on answers are logged and used to re-weight retrieval over time, so the system gets measurably better at your corpus the more it's used.

→ feedback store + ranking adjustment

Evaluation Methodology

A trust claim is only as good as how it was tested. This section defines exactly how "grounded," "accurate," and "≥ 0.85 faithfulness" get measured — not just asserted.

Golden Dataset

A hand-curated set of ~80–120 question/answer/source-citation triples built from the team's own test corpus (mixed PDFs, contracts, papers). Includes three deliberate categories: answerable questions with a clear source, unanswerable / out-of-corpus "trap" questions that should trigger a refusal, and ambiguous questions that require synthesis across multiple chunks. This set is frozen by Week 4 so later changes are measured against a stable baseline, not a moving target.

RAGAS Metrics Tracked

Faithfulness

Does every claim in the answer trace back to retrieved context? Directly correlates with the trust score's entailment check.

Context Precision / Recall

Of the retrieved chunks, how many were actually relevant — and did retrieval miss anything that was?

Answer Relevance

Does the answer actually address the question asked, independent of grounding?

Refusal Accuracy

Custom metric (not stock RAGAS): % of "trap" questions correctly refused vs. hallucinated.

Human Review Process

RAGAS scores are LLM-judged and can be gamed by fluent-but-wrong answers, so every team member manually reviews a 20-question sample each week against the golden set and flags disagreements with the automated score. Disagreements get logged and used to recalibrate the trust-score thresholds in Section 05, not silently ignored.

Hallucination Benchmark

Run weekly starting Week 4: the trap-question subset of the golden dataset is replayed end-to-end and refusal accuracy is plotted over time. This is the chart in the final report that actually proves the "self-verified against hallucination" claim in the executive summary — without it, that claim is just marketing copy.

Why this matters for grading: a reviewer's first question to any RAG project is "how do you know it's actually grounded, and not just confidently wrong?" This section is the answer — point to the golden dataset and the weekly benchmark chart, not just the RAGAS dashboard number.

Development Roadmap — 8 Weeks

Three explicit phases, not eight equal weeks. MVP is the project that must exist by Week 4 even if everything after it slips — V2 and V3 are additive, never load-bearing.

MVP Weeks 1–4

Upload → hybrid retrieval → re-rank → cited, streaming answer. A complete, demoable product on its own. This is what gets graded if nothing else ships.

V2 Weeks 5–6

Trust score + "Why this answer?" panel + auth/workspaces. The signature differentiators, built only on top of a working MVP.

V3 Weeks 7–8

CRAG self-correction, multimodal, feedback learning, analytics dashboard. Ship whichever of these is on schedule — none of them block the demo.

Non-Functional Requirements

⚡ Performance

Median answer < 4s on a 16 GB laptop; ingestion of a 100-page PDF < 60s. Streaming starts within 1.5s.

🔐 Privacy & Security

No data leaves the machine. Tokens/PII never logged. JWT-secured API, hashed passwords, workspace isolation.

📈 Scalability

Handle ≥ 10k chunks per workspace; concurrent multi-user queries via async FastAPI.

♿ Usability

Responsive UI from 360px, accessible contrast, keyboard navigation, clear empty/loading/error states.

🔧 Maintainability

Modular services, typed contracts, > 70% test coverage on retrieval & generation logic.

🚀 Portability

One-command Docker run; deployable to any free host or fully offline.

Out of Scope (v1.0)

  • Fine-tuning a custom foundation model from scratch (we use pretrained open models).
  • Real-time collaborative editing of documents.
  • Native mobile apps (responsive web only).
  • Paid cloud LLM fallback — the project is deliberately 100% free and offline.
  • Enterprise SSO/SAML integrations (basic JWT auth only).
